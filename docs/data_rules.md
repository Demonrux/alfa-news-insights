# Правила работы с данными

Исходные данные обезличены и используются только внутри решения. Здесь описаны правила чтения и очистки трёх таблиц.
## Таблицы

| Файл | Содержание |
|---|---|
| `df_Uid_data_hack.csv` | Юридические лица: профиль, отрасль, продукты банка, выручка, группа |
| `df_Fid_Uid_link_hack.csv` | Связи физических лиц с компаниями |
| `df_Uid_payment_hack.csv` | Платежи между компаниями: получатель, плательщик, сумма, число операций |

Формат: CSV, разделитель `;`, кодировка UTF-8.

## Юридические лица

- **Тип клиента** (`CL_TYPE`) принимает три значения: `CLIENT` (действующий клиент), `PROSPECT` (потенциальный, без доступа в интернет-банк), `CLOSE_CLIENT` (бывший клиент). Лента и демо строятся только для `CLIENT`.
- **Выручка** (`REVENUE_COMPANY`) — за 2025 год, в рублях. Значение 1000 — техническая заглушка; нули и пустые значения тоже означают отсутствие данных.
- **Группа компаний** (`GROUP_ID`) объединяет юрлица по доле владения, общему бенефициару или единоличному исполнительному органу.
- **Крупный бизнес** определяется по выручке группы свыше 15 млрд руб., а не по отдельному юрлицу. Такие группы могут встречаться и в среднем бизнесе.
- Выручка группы — сумма выручки её юрлиц из таблицы без заглушек, включая потенциальных и бывших клиентов. Это нижняя оценка: в таблице могут быть не все юрлица группы.
- **`NEGATIVEMARK`** — есть ли у банка достоверные сведения о ключевом собственнике.
- **ФТС:** указаны только страны, без направления торговли. Страна берётся только там, где она заполнена; флаг без страны не трактуется как отсутствие внешней торговли.
- **Повторяющийся идентификатор** — артефакт обезличивания: под одним ID записаны разные компании. Такие строки исключаются из таблицы юрлиц и из платежей, потому что платёж нельзя отнести к конкретной компании.
- Коды ОКВЭД нормализуются по написанию (например, `41.2` и `41.20` — один код).

## Связи физических лиц

- Физическое лицо может быть связано с несколькими компаниями. Вход в демо выполняется под физлицом; полномочия считаются проверенными при входе.
- `CITY_NAME` и `RC_NAME` — город и регион обслуживания юрлица.
- Профиль строится только для компаний, которые есть в таблице юрлиц.

## Платежи

- `PAY_AMT` — сумма в рублях, `PAY_CNT` — число операций. Период начинается с 1 января.
- **Переводы компании самой себе** (плательщик совпадает с получателем) — перемещение средств между своими счетами. Они занимают большую часть объёма. Из анализа контрагентов они исключаются.
- **Контрагент, которого нет в таблице юрлиц:** сведения о нём не собраны, профиль не восстанавливается. Такие платежи учитываются только как объём и число операций, без выводов о контрагенте.
- **Платёж подтверждает факт взаимодействия, но не тип отношений.** Характер связи оценивается только по косвенным признакам: общая группа, отрасль, регион. Предполагаемые связи показываются как гипотезы с указанием подтверждений и степени уверенности.
- Платежи внутри одной группы показываются отдельно от платежей внешним контрагентам.

## Синтетические данные

Реальные данные в репозиторий не попадают. Для проверки решения в комплект входят синтетические данные. Их структура совпадает со структурой таблиц выше.
